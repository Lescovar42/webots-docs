> **Scope** — Representative investigation of the OP3 tmux launcher and op3_manager hardware bringup on branch `ORION_NEW` (commit `dba5be3fefbada854b8d6c11d6655f479b482574`). Not exhaustive. All commands are found in source but remain **untested**. See shared architecture details in [shared card](/shared/manager), [shared card](/shared/teleop) and [shared card](/shared/walking).

## 1 Prerequisites

The launcher performs a **health check** on every run (`health_check` in [source/scripts/op3_tmux/lib/health.sh:L259-L277](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/health.sh#L259-L277)). It requires:

| Check | Details |
|---|---|
| `tmux` | Installed; script can prompt `sudo apt install tmux` ([source/scripts/op3_tmux/lib/health.sh:L5-L23](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/health.sh#L5-L23)) |
| `ros2` | On PATH |
| Built workspace | `op3_joy_teleop` must be findable via `ros2 pkg prefix` ([source/scripts/op3_tmux/lib/health.sh:L271-L277](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/health.sh#L271-L277)) |
| Setup file | Auto-detected in `$WS/install/` (prefers `.bash` / `.sh`; falls back to `.zsh`) ([source/scripts/op3_tmux/lib/health.sh:L100-L132](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/health.sh#L100-L132)) |
| Webots (simulation) | Binary on PATH or `WEBOTS_HOME` set; skipped for `--doctor` if not required |

A fuller diagnostic runs via `./main.sh --doctor` ([source/scripts/op3_tmux/lib/health.sh:L279-L376](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/health.sh#L279-L376)), which additionally verifies `colcon`, `rosdep`, `gum`, `ttyd`, `docker`, Webots and several ROS packages (`rosbridge_server`, `octomap_*`, `webots_ros2_driver`, `foxglove_bridge`, `joy`).

## 3 Profiles (simulation vs physical robot)

## 4 Starting the stack (untested procedure)

The following steps are derived from the argument parser and are **not executed**.

1. **Choose a launch profile.** Use `--profile webots` (default, for simulation) or `--profile real_robot` (physical Jetson).
2. **Select components.** Pass flags like `--base`, `--teleop`, `--foxglove`, `--all`, `--demo`, `--studio`, etc. ([source/scripts/op3_tmux/lib/args.sh:L1-L98](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/args.sh#L1-L98)). For interactive selection, run without flags; `gum` menus appear if installed.
3. **Run the launcher.** Example (untested):
   ```
   ./source/scripts/op3_tmux/main.sh --profile webots --base
   ```
   This starts Webots in Pane 0 and the manager in Pane 1 ([source/scripts/op3_tmux/lib/args.sh:L45-L46](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/args.sh#L45-L46)).
4. **Attach later** with `./main.sh --attach` ([source/scripts/op3_tmux/lib/args.sh:L182](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/args.sh#L182)).
5. **Stop everything** with `./main.sh --exit` or `./main.sh -x` ([source/scripts/op3_tmux/lib/args.sh:L188](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/args.sh#L188)).
6. **Free the Dynamixel port** if the manager died but still holds `/dev/ttyUSBx`: `./main.sh --free-port` ([source/scripts/op3_tmux/lib/args.sh:L40](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/args.sh#L40)).

## 5 op3_manager and serial port discovery

The physical-robot manager launch file `op3_manager.launch.py` auto-detects the OpenCR/Dynamixel serial device ([source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L22-L37](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L22-L37)). It:

- Scans `/dev/ttyUSB0` through `/dev/ttyUSB9` for a writable port ([source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L31](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L31)).
- Falls back to `/dev/ttyOP3` (a udev symlink) or the preferred default `/dev/ttyUSB0` ([source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L35-L37](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L35-L37)).
- Accepts an override via the `OP3_DEVICE` environment variable ([source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L28-L30](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L28-L30)).
- Generates a **patched temporary** `OP3.robot` file with the detected device replacing hard-coded port paths, then registers cleanup at program exit ([source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L40-L58](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L40-L58)).

The manager node starts with parameters `angle_unit: 30.0`, `gazebo: False` and the detected `device_name` ([source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L76-L90](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L76-L90)).

## 7 Configuration overrides

Every component command can be overridden by environment variables ([source/scripts/op3_tmux/lib/args.sh:L87-L102](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/args.sh#L87-L102)). Examples:

- `OP3_MANAGER_CMD` — custom manager launch
- `OP3_START_DELAY_SEC` — delay between Webots and Manager
- `OP3_SHELL_RUNNER` — force `"zsh -lc"` or `"bash -lc"`
- Preferences persist in `~/.config/op3-stack/prefs.sh` ([source/scripts/op3_tmux/lib/health.sh:L32-L38](https://github.com/ProgramBascorro/motion_webots/blob/dba5be3fefbada854b8d6c11d6655f479b482574/scripts/op3_tmux/lib/health.sh#L32-L38))
