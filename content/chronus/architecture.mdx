# Chronus architecture and interfaces

This guide uses the pinned `CHRONUS_NEW` source snapshot. It reviews the manager startup path, selected controller declarations and the launch function. It does not import Alphonse's calibration, serial identities or launch-argument names. No build, ROS launch, simulator, serial access or robot action was performed.

## Launch and serial configuration

The launch function first calls `ensure_ports()`, then resolves manager configuration files `offset.yaml`, `OP3.robot` and `dxl_init_OP3.yaml`. The body and side effects of `ensure_ports()` were not reviewed in this pass. Both `device_name` and `sub_controller_device_name` default to `/dev/ttyOP3`; the launch comments describe a same-bus configuration and an alternative firmware/USB arrangement. [source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L165-L195](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L165-L195)

The node creates `op3_manager`, obtains the `RobotisController` singleton, and declares/reads those two serial parameters, configuration paths and baud rate. Chronus uses the parameter spelling `sub_controller_device_name`; Alphonse's similarly purposed argument must not be assumed interchangeable. [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L246-L268](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L246-L268)

There is a source inconsistency worth resolving on the actual robot: manager comments describe separate micro-USB and servo paths, whereas the inspected launch defaults use the same path for both roles. This review records the differing assumptions and does not certify either wiring arrangement. Inspect the robot configuration and actual port mapping before operation. [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L70-L76](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L70-L76) [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L281-L288](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L281-L288) [source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L173-L195](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L173-L195)

## Initialization and motion modules

The manager declares `simulation` with a false default. In the non-simulation path it opens the sub-controller port and attempts power and LED writes. Its simulation branch instead reads `simulation_robot_name`. These are distinct execution paths; the physical path is not a harmless connectivity-only check. [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L277-L335](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L277-L335)

Startup fails for an empty robot-file path or unsuccessful controller initialization. It optionally loads offsets, registers the OpenCR sensor module and seven motion modules, then starts the controller timer. The subsequent code invokes `goToInitActionPage()` and logs a page-2/WALKING_READY message. This is source behavior and a source log message, not verification of motion contents or a successful pose on Chronus. [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L337-L375](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L337-L375)

The controller header declares initialization and module/timer APIs, control-module and offset functions, ROS callbacks/services and low-level joint operations. Its thread members describe the class structure; scheduling guarantees require the implementation and runtime to be inspected separately. [source/src/ROBOTIS-Framework/robotis_controller/include/robotis_controller/robotis_controller.h:L60-L75](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-Framework/robotis_controller/include/robotis_controller/robotis_controller.h#L60-L75) [source/src/ROBOTIS-Framework/robotis_controller/include/robotis_controller/robotis_controller.h:L120-L162](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-Framework/robotis_controller/include/robotis_controller/robotis_controller.h#L120-L162)

## ROS and health interfaces

The manager subscribes to `/robotis/open_cr/button` and `/robotis/dxl_torque`, and publishes initial-pose, control-module, action-page and ball-tracker command topics. Whether other nodes are connected remains a runtime question. [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L270-L275](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L270-L275)

The `/robotis/health_check` Trigger service returns a skipped/simulation payload when simulation is enabled. On the physical path, it remembers the timer state, stops a running timer, pings configured joints, restores the timer if needed, and constructs a payload listing successful and failed joints. The outer `success` flag is set true after constructing that payload even when the failed-joint list may be nonempty; interpret the payload rather than treating that flag alone as proof of healthy hardware. No service call was made here. [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L377-L442](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L377-L442)

## Unresolved configuration and documentation issues

Launch supplies `gazebo`/`gazebo_robot_name`, while the manager reads `simulation`/`simulation_robot_name`. The inspected code does not demonstrate a bridge between those parameter names. Verify the effective node parameters before assuming that a launch setting selects simulation. [source/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py:L187-L195](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/launch/op3_manager.launch.py#L187-L195) [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L277-L279](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L277-L279) [source/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp:L326-L335](https://github.com/ProgramBascorro/motion_webots/blob/54998e7c56e5b2cce4c1c533758c7d2f2cf7698b/src/ROBOTIS-OP3/op3_manager/src/op3_manager.cpp#L326-L335)
